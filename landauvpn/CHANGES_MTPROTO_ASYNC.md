# Изменения в модуле MTProto Proxy Controller

## Дата: 2024

## Резюме

Модуль `mtproto/controller.py` был полностью переработан с использованием **асинхронного программирования** для эффективной проверки доступности прокси-серверов Telegram.

## Ключевые изменения

### 1. Асинхронная архитектура

- Добавлен `asyncio` для параллельной проверки прокси
- Все 156 публичных прокси проверяются одновременно (~5-10 сек вместо ~13 мин)
- Фоновый асинхронный цикл для периодической проверки

### 2. Умное исключение нерабочих прокси

Каждый прокси теперь имеет:
- `is_alive: bool` - статус доступности
- `latency: float` - задержка в мс
- `fail_count: int` - счётчик неудач
- `last_checked: float` - время последней проверки

После `max_failures` (по умолчанию 3) неудачных проверок прокси автоматически:
- Помечается как нерабочий (`is_alive = False`)
- Исключается из пула проверенных прокси
- Не учитывается при выборе лучшего прокси

### 3. Новые методы контроллера

| Метод | Описание |
|-------|----------|
| `check_all_proxies_async()` | Параллельная асинхронная проверка всех прокси |
| `test_proxy_async(proxy)` | Асинхронный тест одного прокси с измерением latency |
| `get_working_proxies()` | Получить рабочие прокси, отсортированные по задержке |
| `get_stats()` | Статистика: всего/рабочих/исключено/средняя задержка |
| `reset_failed_proxies()` | Сбросить счётчики неудач (при изменении сети) |
| `start_async_checker()` | Запуск фонового асинхронного проверщика |

### 4. Обновлённая конфигурация

```python
@dataclass
class MTProtoConfig:
    enabled: bool = True
    auto_detect: bool = True
    timeout: int = 5              # Таймаут подключения
    retry_count: int = 3          # Попытки переподключения
    check_interval: int = 60      # Интервал периодической проверки (сек)
    max_failures: int = 3         # Порог исключения прокси
    min_working_proxies: int = 5  # Минимальное кол-во рабочих прокси
```

### 5. Улучшенный мониторинг

При запуске `controller.start()`:
1. Выполняется начальная асинхронная проверка всех прокси
2. Выбирается лучший прокси (минимальная задержка)
3. Запускается фоновый поток для авто-переподключения
4. Запускается асинхронный проверщик для периодического обновления статуса

## Примеры использования

### Быстрая проверка прокси

```python
from mtproto.controller import MTProtoController
import asyncio

controller = MTProtoController()

async def check():
    results = await controller.check_all_proxies_async()
    working = sum(1 for ok in results.values() if ok)
    print(f"Рабочих: {working}/156")

asyncio.run(check())
```

### Авто-выбор лучшего прокси

```python
controller = MTProtoController()
controller.start()  # Автоматически проверит и подключится

# Получить текущий прокси
current = controller.get_current_proxy()
print(f"Подключено к: {current.host}:{current.port}")
```

### Мониторинг статуса

```python
stats = controller.get_stats()
print(f"Всего: {stats['total']}")
print(f"Рабочих: {stats['working']}")
print(f"Исключено: {stats['failed']}")
print(f"Средняя задержка: {stats['avg_latency']:.0f}ms")
```
